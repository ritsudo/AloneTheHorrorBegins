## Move the project

Copy this whole directory to the next machine and keep the same relative layout:

```
AloneTheHorror/
  build.ps1  src/  res/  bin/  docs/  tools/  alonehorror_demo_frames/
```

`src/`, `res/`, `docs/`, `tools/` and `alonehorror_demo_frames/` are the
important ones; `classes/`, `tmpclasses/`, `bin/` are regenerated by the build.

## Toolchain on the new machine

`build.ps1` hard-codes two paths — edit the top of the script if they differ:

```powershell
$JDK  = "D:\Java\jdk1.8.0_131\bin"
$WTK  = "D:\Java\WTK2.5.2_01"
```

Requirements: a **32-bit JDK 1.8** and **Sun WTK 2.5.2** (for `preverify`,
`cldcapi11.jar`, `midpapi20.jar`, `emulator.exe`). Python 3 + Pillow for the
asset pipeline.

## Build / run

```powershell
powershell -ExecutionPolicy Bypass -File build.ps1
```

Verify the JAR packaged: `bin\AloneTheHorror.jar` should be ~280 KB and contain
all `res/*.png` plus `horror.class`.

## EMULATOR WARNING

Do **not** run the WTK emulator on a machine with limited RAM — it has crashed
the dev VM (VMware RAM fault). Run only where >= 6 GB RAM is available:

```powershell
powershell -ExecutionPolicy Bypass -File build.ps1 -Run
```

Helper scripts (`tools/emu/`) launch the emulator and capture screenshots; from
the AMS use `F2` (right soft key) then the fire key to start the MIDlet.

## Session 5 addenda

- Final art/maps live in `sdk-map-editor/assets/` and
  `sdk-map-editor/maps/`. Never run the old ch1/map_sync generators over
  them; use `python tools/integrate_final.py` to publish them to `res/` and the
  editor bundle.
- Game objects are catalogued once in
  `sdk-map-editor/assets/game_objects.json` (items, enemies, triggers).
- Story triggers: 4612 `talk_jonathan` (chapter 1 ending), 4613 `door_crowbar`
  (chapter 3 ending; without the crowbar it only shows a jammed-door message).
- The editor object inspector edits type/x/y/param/flags. Cutscene params index
  `Script.cut`; new objects default to param 1.

## Session 4 addenda

- Tileset is the 8x8 grid `res/tileset_grid.png` (id = row*8 + column, grouped
  by type). Rebuild atlas + maps + editor bundle together with
  `python tools/build_grid.py`; it also repairs collision and the object layer.
- Spawns are map triggers (`type 4608`), not the 0,0 corner. Chapter 1 spawns at
  tile 12,25 (the red square in `assembly_example/map_recovery.png`).
- Open `sdk-map-editor/editor/index.html` after rebuilding the bundle. Click an
  object in the Objects layer to edit its type/x/y/param/flags (the param is the
  cutscene index used by `Script.cut`).

## Session 3 addenda

- **CLDC gotchas hit and fixed** (keep them fixed):
  - no `static final byte[]` mega-initialisers - a >32 kB method limit
    throws OutOfMemoryError at runtime (`JMapData` is gone; maps load from
    the JAR instead);
  - use `getClass().getResourceAsStream(...)` on an INSTANCE or
    `MIDlet.getResourceAsStream` - `World.class.getResourceAsStream`
    (class literal) makes javac emit `NoClassDefFoundError.initCause`,
    which CLDC lacks.
- **Per-chapter atlases**: `res/tileset_ch1.png` (chapter 1 only, 526
  tiles) is picked in `World.load` via `TileMap.useAtlas`; `res/tileset.png`
  serves chapters 2-3. Both quantised to 255-colour PNGs.
- **Map/cutscene data flow**: `sdk-map-editor/tools/rebuild_maps.py` writes
  `res/chapter*.jmap` + `res/tileset.png` (terrain + collision + objects);
  cutscene trigger params index the tables in `src/Script.java`, whose text
  comes verbatim from `docs/analysis/dlg_script.txt` (recovered by
  `tools/dialogue_recover.py` + `tools/dialogue_finalize.py`).
- **If `powershell -File` returns -1 from Git Bash**: run the four build
  steps directly (see PROGRESS.md) or retry from a native console;
  `tools/emu_driver.py launch|keys|shot` drives the emulator in pure Python.
